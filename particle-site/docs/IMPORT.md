# 图片与静态 GLB 导入

v0.2 已把该模块接入工作台的素材导入窗口：支持文件选择、拖入及示例加载，显示文件名、类型、状态、实际数量和中文说明。并发优先级由界面处理，成功后才替换当前场景。

## 用户图片示例

`public/examples/particle-flower-reference.jpg` 是用户提供的原图副本，736 × 981、RGB、87,822 字节。它用于花朵示例及默认原色 / 60,000 粒子展示，配合 12 秒侵蚀卷流、淡出和反向还原关键帧；独立百合 GLB 示例仍为 80,000 粒子。导入模块保留整张 JPG，黑背景参与采样，不自动抠黑底；黑色粒子在黑色背景下较不显眼。

这是图片在三维空间中的二维平面粒子阵列，保持纵向比例；侧面较薄属于预期。消散位移可进入三维空间，但不实现单张图片的三维重建。新图片的真实浏览器视觉和性能检查由本轮现场 QA 补录。

模块：`src/assets.ts`。此模块只解析和生成数据，不修改编辑器当前场景；成功返回 `ParticleAsset` 后，由界面决定是否替换。导入失败抛出中文 `Error`。界面负责加载状态、最后一次选择优先及保留旧场景。

## 数据契约

`ParticleAsset` 包含素材名、`sphere / image / model` 类型、实际采样池 `count`、原始位置、线性 RGB、稳定随机种子、是否可用原色、中文说明和可选缩略图。位置与颜色均为每粒子 3 个数；`seeds` 同样为 3 个 0–1 数。

最大采样池为 100,000。调粒子数量使用同一池的前缀，因此增减密度不重新抽取位置。种子固定为确定性 xorshift 序列。位置使用统一比例居中并缩放，采样点距中心不超过 1.35；不会分别拉伸 X / Y / Z。图片使用全部有效像素的边界居中，避免采样池上限使图像中心偏移。

导出入口：

- `loadParticleAsset(file)`：PNG / JPG / JPEG / 静态 GLB。
- `createSphereAsset()`：100,000 个稳定球体表面采样点。
- `loadExampleAsset(url, name)`：读取本机预览提供的示例文件。
- `sampleImagePixels()`、`sampleModelScene()` 等纯采样接口供测试使用；`sampleModelScene()` 不释放调用方的场景。

## 图片算法

1. 解码前先检查文件不超过 50 MiB，并读取前 1 MiB 中的 PNG IHDR / JPEG SOF 尺寸；拒绝超过 3,600 万像素、无有效尺寸或无法安全读取头部的图片，给出缩小 / 重新导出的中文说明。优先使用 `createImageBitmap` 解码，再按原比例绘制到 2D 画布；采样画布最大边为 2,048 像素，原文件不修改。不支持 ImageBitmap 的浏览器回退到本地 Object URL 图片。
2. 仅 Alpha 大于 0 的像素有效。完全透明的 PNG 明确报错；JPG 没有透明背景，整图参与采样。
3. 先收集全部有效像素索引，再使用固定种子的 xorshift 驱动 Fisher–Yates 洗牌，取洗牌后序列的前缀。洗牌一次为 O(有效像素数)，不重复生成同一像素；相同输入重复导入得到相同序列，增减数量只改变稳定前缀长度。实际数量为有效像素数与 100,000 中较小值；不足时返回说明。
4. 根据完整有效像素区域计算边界中心和包围半径，像素中心映射到 XY 平面，Y 朝上、Z 固定为 0。X / Y 使用相同缩放比例，保留原图的比例和内部空间关系；不对透明外边距单独拉伸。侧面观察时较薄属于预期。
5. 浏览器返回的 sRGB 像素转换成线性 RGB，供 GPU 使用。Alpha 用于过滤，不作为每个粒子的独立透明度；最终粒子透明度由编辑器统一参数控制。包含半透明像素时返回此说明。
6. 缩略图最大边为 240 像素。成功或失败均关闭源 ImageBitmap、释放回退 Object URL、清空临时图片与画布尺寸。

图片缩小后采样会减少细节；极小图片可能少于 1,000 个有效粒子。编辑器应显示实际数量，避免用请求数量冒充生成数量。尺寸头预检限制单张图像的原始解码内存，而 2,048 边长控制后续采样内存；浏览器解码过程中仍可能产生额外副本，不将这一保护描述为内存占用的精确上限。

2026-10-23 视觉回归修复：旧版对展开的一维像素索引做位反转，再截取前 N 个。它会与部分图片宽度产生周期共振；736 像素宽参考图出现每 16 / 8 列取点的规律性空隙，聚合画面形成竖条纹。现改为上述固定种子洗牌，避免按整列规律取样。颜色、透明过滤、居中比例、最大数量及对外参数不变；新版采样位置会与旧版不同，但新版自身重复导入和数量前缀保持稳定。新增 736 × 981 采样密度回归已通过，全项目最终 Node 75/75、TS 与构建成功；修复后真实图片与录像 43/43 通过，主界面目视竖条纹已消除。最终结果见 `SYSTEM-REPAIR.md`，旧首轮结果另行保留。

## GLB 算法

1. 读取前先检查文件不超过 100 MiB。检查 glTF 2.0 二进制头及 JSON，拒绝损坏文件、所需 Draco / Meshopt 压缩或 KTX2 贴图，以及对外部文件的引用。本版本要求所有几何和普通图片贴图内嵌于 GLB。
2. Three.js `GLTFLoader` 读取场景；更新全部世界变换，支持多个普通静态网格及父子节点的位置、旋转、缩放。
3. 逐个有效三角面在世界坐标中计算面积，按面积累计分布选择三角面；再用平方根变换生成均匀重心坐标。这保证缩放后的大网格获得更多采样点。
4. 骨骼、形变目标、实例化、点、线、退化及无效三角数据被跳过并提示。没有有效静态三角面时失败；超过 1,000,000 个有效三角面时提示先简化。
5. 生成 100,000 个稳定表面点，双精度计算和居中后再转为 Float32，避免很大的节点平移抹去局部形状；完整采样池统一居中、等比例缩放。
6. 颜色 = 材质基础色 × 线性顶点颜色 × 按 UV 读取的基础色贴图。支持贴图对应 UV 通道、变换、重复 / 镜像 / 钳位及 `flipY`。基础贴图采样画布最大边 2,048，采用最近像素；sRGB 贴图先转成线性 RGB。
7. 贴图无法加载 / 读取、缺少 UV 或 UV 值 / 变换无效时回退材质基色 / 顶点色，并返回提示；顶点颜色不完整或非有限值时不参与颜色乘法；无基础颜色时回退淡紫色，可选择统一色模式。透明材质返回基础 RGB 与统一透明度的限制说明。
8. 采样结束后释放全部 glTF 场景（包括未显示场景）的几何、材质、贴图、共享 ImageBitmap 及临时 Blob URL；跨场景共享对象去重，仅释放一次。实际渲染使用独立数组，不继续持有原模型场景。

本轮不实现骨骼动画、动画播放、形变、压缩解码、体积内部填充、真实材质光照、法线 / 金属度 / 粗糙度贴图或透明材质的逐点 Alpha。存在普通节点动画时采样静态初始姿态并提示。UV 贴图颜色取样以基础色还原为目标，不等同完整材质渲染。
