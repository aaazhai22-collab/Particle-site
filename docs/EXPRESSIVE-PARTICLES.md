# 粒子质感与设备自适应数量

更新时间：2026-10-24（北京时间）。本轮在既有六种效果、图片 / GLB 原色、可逆聚散、时间轴与 720p 本地录制之上增强粒子质感和数量调度。相机变更重绘修复后的最终验收完成：Node 110/110、真实 GPU 28/28、浏览器专项 51/51，TypeScript 与 Vite 生产构建通过；主界面数量切换、暂停滚轮、播放和两种桌面布局已人工复验。发布状态独立记录于本地 `artifacts/expressive-release.json`，以同一提交的 Site 版本与部署工具返回为准。

## 视觉目标与边界

- 原形聚合时保留素材轮廓和原色分区；0% 时消散偏移严格归零，不用历史位置积分累积误差。
- 增强细粒子亮核、发光溢出、曝光 / 对比和卷曲流场。亮核与 Bloom 分开控制，避免一味放大粒子把原色混成白色。
- 消散保持逐点的 XYZ 空间结构、区域关联与局部细流；六种效果仍可切换，末段淡出同时影响粒子、细流与发光。
- 图片聚合仍是二维平面；空间粒子运动不等于通用单张图片形状重建。JPG 黑背景保留，PNG 全透明像素不采样，现有模型静态表面限制不变。
- 发光和后处理必须进入最终捕获画布，使录像包含实际亮核、Bloom、拖尾和淡出；面板与测试文字不入画。

当前接口为 `exposure`（0.3–3，通用初值 1.3）、`contrast`（0.5–2，通用初值 1）、`curl`（0–3，通用初值 1.2）、`sparkle`（0–1，初值 0.35）。`glow=0` 关闭真实 Bloom，曝光与对比仍保留最终输出处理。QA 固定粒子本身的 glow uniform 为 0.7，再比较后处理开关，避免仅因粒子变大或亮核变化而误判 Bloom 生效；最终画布实际差异已通过检查。

用户批准的参考展示与 QA 基准采用：粒子大小 1.7、柔光 0.7、曝光 1.55、对比 1.05、卷曲 1.8、拉丝 2.2、拖尾 0.65、独立散开 0.18、深度 1.35、扩散 1.15、运动速度 0.55。此预设与引擎通用初值分开记录；颜色继续用素材原色。录制保留同一参考参数，仅开启末段淡出，不临时更换成旧视觉配置。

## 自动与手动数量

1. 图片和静态模型的最大稳定采样池已提升为 500,000。图片实际可用量仍受有效像素数约束，不复制同一像素冒充更多独立粒子；小图显示实际数量。
2. 手动模式允许用户选择较高数量，并即时显示真实绘制量。增减数量使用稳定、唯一的采样前缀，保留当前视角、进度和播放任务。
3. 自动模式依据实际活动渲染样本与稳定窗口调整数量；有余量才逐步提高，压力持续增大时下调。静止按需渲染、隐藏页和录制暂停的低 FPS 不应被当作普通活动性能样本。
4. 自动数量是设备与当前效果共同决定的结果，不保证所有 GPU 都上调，也不以某台设备固定达到高数量作为通过条件。显示实测数量和调节状态，手动选择后明确转为手动模式。
5. 录制开始冻结实际数量，录制暂停期间继续冻结，完成或取消后按原模式恢复调度，避免录像期间突然改变密度。`setRecordingLocked(true)` 覆盖录制、暂停与生成阶段；`setCaptureActive(true)` 只在实际写入帧时开启，连续捕获与自动数量冻结分别验证。

控制器采用约 2 秒真实活动时间窗与迟滞，持续有余量时升档、持续低帧率时降档，偶发单次卡顿不骤降。升降压、暂停与冻结边界纳入自动回归；本机浏览器实际观察到升档，不把该设备自然运行未出现的降档过程写成已现场发生。设备记录只反映实际采样，不依据 GPU 名称预填数量。

## 开发验证页

入口：开发服务器的 `/expressive-qa.html`。独立于产品界面，只在本地开发环境执行；复用真实 `loadParticleAsset`、`ParticleEngine`、`CanvasRecorder` 与现有 `/__qa` 保存接口，不创建模拟录制数据。

已执行的专项检查：

- 真实 PNG / JPG 原色、六效果中间态、0% 精准还原、暂停像素稳定与末段完全淡出；另读取真实方鼎 GLB 检查 500,000 池、非单色贴图颜色、原形、中间态、侧面与反向还原。模型和图片复用同一个引擎，不创建实体对照渲染器。
- 最终 canvas 中 Bloom 开关的真实亮度差、曝光 / 对比 / 亮核 / 卷曲的实际影响；不是只检查参数值改变。
- 180,000 / 300,000 / 500,000 手动数量与真实 GPU 绘制范围；微型透明 PNG 的有效像素上限与实际数量。
- 至少 60 秒活动自动调度（验证页设为 60.5 秒），逐秒记录渲染 FPS、实际数量与状态；自动测试上限为 300,000，手动另验证到 500,000。按实际设备报告观察，不要求必须上调到某个数值；升降压边界另由纯函数回归补充。
- 至少 11 秒有效 1280 × 720、目标 30 FPS 无声录像，包含发光与轨迹；暂停约 1.5 秒不计有效时长，录制与暂停期间实际数量冻结。
- 同一保存视频的 metadata、尺寸、中段 seek、播放与暂停；实际编码 FPS 由容器样本另行解析，与渲染 FPS 分开记录。

验证期间只每秒更新简短状态；录制时不生成 PNG、不频繁刷新整份报告，不调用自动下载工具。可通过聚合、半消散、细流、暂停及对照按钮人工观察。真实 Blob 和 JSON 写入 `artifacts/browser-test.*`，运行前备份需要保留的历史证据。

方鼎不能只凭 `hasOriginalColors=true` 判断纹理成功：默认白材质也可能满足该标记。验证页同时检查颜色数组有限、具有多个颜色区间与亮度变化、无贴图回退提示，并对照真实原色 / 统一白色的最终画布。500,000 个位置、颜色、种子数组合计约 18 MB，只是最终采样数组；贴图解码、采样缓存、模型三角表与 GPU 后处理另占内存，不把该数值当作总峰值。

## 首次失败与精度界限

暂停时相机变化曾没有触发静态按需渲染，滚轮后的画面需要其他变化才更新。现已补相机变更重绘并重新执行全部浏览器专项。[修复前相机未重绘的裁剪截图](../artifacts/expressive-camera-stale-before.jpg) 仅为该缺陷的证据，不作为最终效果展示。

首次真实 Bloom 对照发现开关画面 SHA 和亮度完全相同，保留于[首次失败报告](../artifacts/expressive-first-browser-test.json)。原因是 HDR 提取阈值 0.72 对细颗粒过高，现降至 0.08 后重测；不是修改通过条件掩盖没有发光。最终固定粒子 shader glow 的对照中，Bloom 关闭 / 开启均值由 **0.0012407107 → 0.0044333816**，发亮像素 **7,702 → 49,566**，画面 SHA 不同，确认后处理进入最终画布。曝光、对比、卷曲及亮核也分别改变真实渲染。

方鼎原色 → 白色 → 原色曾因严格 SHA 不同而停止，保留于[舍入失败报告](../artifacts/expressive-rounding-browser-test.json)。现逐个比较 1280 × 720 的 **2,764,800 个 RGB 通道**，不凭均值相近放行：仅允许最多 64 个通道各差 1 个 8 位色阶（1/255）。实际原色恢复及空间消散后归零都只有 **1 个通道相差 1 级**，平均绝对差 **3.616898 × 10⁻⁷ 色阶 / 通道**；位置、颜色、种子源数组仍为同一对象，progress 严格为 0、拖尾关闭、原色 uniform 为 1。暂存原始像素最多三张，不序列化。

这一容差只用于方鼎最终后处理画布的极少量颜色舍入。PNG / JPG 仍用严格 SHA 还原，真实 GPU 28 项中的原坐标归零、往返不积累和六效果空间检查仍为原有严格判断，不以颜色容差放宽几何正确性。

保留原有参数 / 关键帧 JSON、预设、素材切换与资源释放行为。1080p、独立录制模板、所有设备 60 FPS、5 分钟 / 多次素材与录像压力验收不因这次质感增强自动视为完成。
